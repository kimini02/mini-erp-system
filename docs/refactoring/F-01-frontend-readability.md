# F-01 프론트엔드 리팩토링 — 화면은 그대로, 읽기 쉽게

명세 [17](../../backend/md/17-refactoring.md) 4장의 프론트 부분. 브랜치 `refactor/frontend-readability`(develop `faf7972`에서 시작). 화면 모양·동작·호출하는 API는 바꾸지 않는다.

## 왜 했나
- 큰 페이지 6개가 600~1,000줄이었다(Prettier 적용 기준). 한 파일 안에 모달·패널이 여러 개 들어 있어, 처음 보는 사람이 원하는 부분을 찾기 어려웠다.
- API 파일 이름이 마일스톤 번호(`api/m1.js`~`m4.js`)라 이름만 보고는 무엇이 들었는지 알 수 없었다.
- 팀 단계의 쓰지 않는 코드와 json-server 목 서버가 남아 있었다.
- 모든 화면이 JS 한 파일(721,560바이트)로 묶여 첫 접속에 전부 내려받았다.

## 안전망 — 무엇을 비교했나
목 모드(`npm run dev:mock`)에서 관리소장 계정으로 화면을 돌며 기록하고, 단계마다 같은 기록을 다시 만들어 비교했다.

| 대상 | 개수 | 비교한 것 |
|---|---|---|
| 화면 | 20 (기안 작성 4개 양식, 문서 상세 포함) | 화면 글자(`innerText`), DOM 전체(`innerHTML`), 그 화면이 부른 API 목록과 순서 |
| 모달·서랍 | 13 (부서 추가·이동·부서장, 사원 등록·수정, 역할 만들기·수정·사원 추가, 공휴일 등록, 연차 부여 기록, 프로젝트 등록, 업무 추가, 업무 상세 서랍) | 모달 DOM, 글자, 연 뒤 부른 API |

이를 위해 목 모드 전용 장치 두 개를 넣었다(`3db4902`, `299d3e8`). 배포 빌드에서는 빠진다. 비교에 쓴 브라우저 콘솔 스크립트는 [F-01-safety-net.js](F-01-safety-net.js)에 있다.
- 고정 시계: `localStorage.__MOCK_NOW__`가 있으면 그 시각으로 멈춘다. 목 데이터는 "오늘" 기준이라, 날짜가 바뀌어도 같은 데이터로 비교하기 위해서다.
- API 호출 기록: 목 서버는 axios 안에서 동작해 브라우저 네트워크 기록에 보이지 않는다. 그래서 목 어댑터에서 `window.__MOCK_CALLS__`에 남긴다.

**가린 값과 뺀 값** (실행마다 달라지는 것만)
- React `useId`(`:r1:` 형태)와 FullCalendar의 `fc-dom-N` id: 전역 번호라 실행 순서에 따라 바뀐다.
- `AppLayout`의 주기 새로고침 요청 묶음(결재 건수·결재 대기 5건·안 읽은 알림): 60초마다, 그리고 창이 포커스를 받을 때마다 보낸다. 기록 시간에 들어올지가 실행마다 다르다. 이 동작은 `AppLayout`에서 따로 확인했고 이번에 바꾸지 않았다.
- 새로고침 직후의 로그인 정보 요청(`/me`, `/me/permissions`): 비교 전에 화면 하나를 먼저 거쳐(예열) 기록에서 뺐다.

**안정성**: 리팩토링 전 코드로 다시 돌렸을 때 화면 20/20, 모달 13/13이 같았다. 새로고침한 뒤에도 같았다.

**배포 빌드 비교**: 동작이 바뀌면 안 되는 단계는 배포 빌드 JS·CSS를 develop 빌드와 바이트 단위로 비교했다.

## 코드 분할이 새로 만드는 위험과 대비
- 배포는 `current` 링크를 새 릴리스로 바꾼다. 예전 화면을 열어 둔 탭이 다른 메뉴를 누르면 이미 없는 예전 조각 파일을 요청하고, Nginx는 `/assets/`에서 404를 준다(`try_files $uri =404`). 분할 전에는 생길 수 없던 실패다.
- 대비 1, `lib/lazyPage`: 조각을 못 받으면 새 `index.html`(no-cache)을 받도록 한 번만 새로고침한다. 10초 안에 다시 실패하면 반복하지 않는다.
- 대비 2, `PageErrorBoundary`: 그래도 실패하면 본문 영역에만 "화면을 불러오지 못했습니다"와 새로고침 버튼을 보여 준다. 사이드바·상단바는 남고, 다른 메뉴로 옮기면 다시 그린다. 지금까지 앱에는 오류 경계가 없어서, 화면 하나의 오류가 앱 전체 흰 화면이 됐다.
- 시험: 공휴일 화면의 조각 경로를 잠시 없는 파일로 바꾸고 그 화면을 열었다. 결과: 같은 주소에서 한 번 새로고침(`navigation type = reload`)한 뒤 오류 화면이 나왔고, 사이드바·상단바는 그대로였다. 시험 뒤 원복했고, 원복한 파일이 검증본과 같음을 확인했다.
- 정적 메서드(`getDerivedStateFromError`)는 클래스 밖에서 대입한다. 소스에 `static`이라는 단어가 있으면 Tailwind가 `.static` 클래스를 만들어 배포 CSS가 바뀌기 때문이다(고정 시계에서 한 번 겪음).

## 안전망이 찾은 기존 버그 (고치지 않음)
명세 17 3장대로 리팩토링 중에는 고치지 않고 기록만 했다.
- **KI-08 캘린더**: 제거된 구 API 5개를 부르고, `/projects`의 페이지 응답을 배열로 가공하다 실패한다. 실제 서버에서도 대부분 동작하지 않는다.
- **KI-09 목 모드 내 프로필**: 목 응답에 `departmentName`이 없어 부서 객체를 그대로 그리다 앱 전체가 흰 화면이 된다. 실제 서버 응답에서는 생기지 않는다.

자세한 내용은 [known-issues](../known-issues.md).

## 하지 않은 것과 이유
- **캘린더 페이지 나누기**: KI-08 때문에 현재 API로 다시 만들어야 하는 화면이다. 지금 나누면 일이 두 번이 된다.
- **목 파일(`api/mock/m2~m4.js`) 이름 바꾸기**: 한 파일에 여러 도메인이 섞여 있어 이름만 바꿀 수 없다. 나누면 목 동작이 바뀔 수 있다. 안전망이 이 목 데이터에 기대므로 이번에는 그대로 둔다(개발 전용).
- **큰 페이지의 본체 더 나누기**: 기안 작성(546줄)·부서(444줄)는 페이지 본체 자체가 길다. 더 나누려면 상태와 로직을 옮겨야 해서 "그대로 옮기기"를 넘는다.
- **픽셀 스크린샷 비교**: DOM 전체와 CSS가 같으면 화면도 같다. 그래서 DOM 비교를 기준으로 삼았다.

## 남은 한계
- 비교는 목 모드, 관리소장 한 계정, 고정 시각 하나에서 했다. 다른 역할(팀장·사원)의 화면과 입력·저장 같은 쓰기 동작은 이번 비교 범위 밖이다.
- 로그인 전 화면(로그인·아이디 찾기·비밀번호 찾기·초대 설정)은 기록하지 않았다. 이번에 바꾼 것은 Prettier 형식뿐이다.
- 코드 분할 뒤에는 화면을 처음 열 때 짧은 로딩 표시가 보일 수 있다. 의도한 변화다.
