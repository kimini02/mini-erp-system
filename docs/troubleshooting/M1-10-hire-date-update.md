# M1-10 — 이관 사원의 입사일 보정

## 증상
V1에는 입사일이 없고, 기존 PATCH는 hireDate를 받지 않아 뒤늦게 확인한 날짜를 반영할 수 없었다.

## 재현 방법
`M1AcceptanceTest.chiefCanFillLegacyHireDateWithoutChangingLoginId`에서 입사일 NULL인 기존 사원에게 날짜를 보내도 NULL로 남았다. 잘못된 날짜 3건도 알 수 없는 필드로 무시되어 200이었다. 수정 전 총 4건 실패를 확인했다.

## 원인
PATCH 요청에 hireDate가 없고 갱신문에도 반영되지 않았다. 기존 자료만으로는 실제 입사일을 추론할 수 없다.

## 검토했지만 버린 방법과 이유
이관일/계정 생성일을 입사일로 채우면 사실과 다른 인사 정보가 된다. 입사일 변경에 따라 로그인 아이디를 재발급하면 기존 로그인과 참조가 흔들린다. 둘 다 적용하지 않는다.

## 선택한 방법
DB는 NULL을 허용하고 기존 값은 NULL로 이관한다. POST는 기존 @NotNull 검증으로 hireDate를 필수로 받는다. PATCH에 선택 필드를 추가하고 yyyy-MM-dd 문자열을 엄격하게 파싱한다(Java 날짜 패턴 uuuu-MM-dd). 존재하지 않는 날짜도 400이다. EMPLOYEE U와 기존 데이터 범위 검사를 유지하며, 날짜만 저장하고 아이디/발급 시퀀스를 바꾸지 않는다. 생략/null인 PATCH 값은 기존 입사일을 유지한다.

## 부작용·남은 위험
NULL 값을 지우기 명령으로 사용하지 않는다. 입사일에 따른 기존 연차 재계산은 이번 요청에 없어 수행하지 않는다. 프론트 브랜치에서 갱신할 명세 파일은 건드리지 않았다.

## 결과
관련 API 테스트 6건 통과: 입사일 보정과 아이디/시퀀스 보존, 다른 필드 수정 시 날짜 보존, 잘못된 형식/불가능한 날짜 3건 차단, 사원 본인 수정 403, 신규 등록의 날짜 누락/null 400. 최종 전체 결과는 M1 보고서에 기록한다.
