# M1 리뷰 4 — 부서장 잠금 순서 재검증

## 증상
부서장 지정과 사원 변경의 경쟁은 이전 c7c9eb2에서 수정했다. 이번 요구사항과 같은 잠금 구조인지 재확인했다.

## 재현 방법
해당 회귀 테스트를 Java 17 + Docker에서 구현 변경 전 실행하고, 변경 후 같은 테스트를 다시 실행한다. 아래 결과에 테스트 이름과 전후 결과를 기록한다.

## 원인
부서장 지정과 사원 변경의 경쟁은 이전 c7c9eb2에서 수정했다. 이번 요구사항과 같은 잠금 구조인지 재확인했다.

## 검토했지만 버린 방법과 이유
화면에서만 제한하거나 테스트 기대값을 낮추는 방법은 서버의 계약을 보호하지 못하므로 사용하지 않았다. 새 라이브러리 없이 기존 구조를 유지한다.

## 선택한 방법
부서 변경 patch와 비재직 status가 공통 DepartmentTreeLock을 먼저 잡고 사용자 FOR UPDATE와 부서장 FOR UPDATE를 수행한다. 중복 구현 없이 기존 실제 MariaDB 경쟁 테스트를 다시 실행했다.

## 부작용·남은 위험
루트 행 직렬화의 대기 비용과 직접 SQL 변경은 이전 M1-12 문서의 범위와 같다.

## 결과
- 이번에는 새 테스트나 운영 코드 변경이 없다. 기존 구현과 회귀 검증을 이 독립 문서 커밋으로 확인한다.
- DepartmentHeadConcurrencyTest 6개 성공. 부서 이동·퇴사·휴직 × 변경 검사 우선/기존 스냅샷 후 부서장 지정 × 각 3회 = 18회 중 위반 0.
- 최초 수정 전 실패 증거는 M1-12-department-head-invariant.md의 18/18 위반 기록을 따른다. 이번 시작 상태에서도 이미 통과했으므로 새로 실패를 재현했다고 보고하지 않는다.
