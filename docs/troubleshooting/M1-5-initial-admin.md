# M1-5 — 최초 관리자

## 증상
최초 관리자는 새 CHIEF 구조와 초기 비밀번호 변경 정책을 따라야 한다.

## 재현 방법
InitialAdminInitializerTest와 InitialAdminMariaDbTest를 실행한다. 누락/공백/정책 위반 환경변수, 기존 관리자, 정상 생성, 재시작 중복 방지를 검사한다.

## 원인
M0는 단일 ADMIN 컬럼을 쓰고 초기 비밀번호 정책/변경 의무가 없었다.

## 검토했지만 버린 방법과 이유
설정 파일의 기본 비밀번호와 자동 보정은 사용하지 않는다. 입력이 잘못되면 계정을 만들지 않는다.

## 선택한 방법
기본 CHIEF 역할과 관리소장 직급을 부여하고 must_change_pw=true로 저장한다. 기존 비밀번호 정책(8~20자, 대문자·소문자·숫자·특수문자)을 공통화했다. 경고에는 환경변수 값이나 토큰을 남기지 않는다.

## 부작용·남은 위험
기존 초기 관리자는 이관만으로 강제 비밀번호 변경 대상으로 바꾸지 않는다. 여러 서버의 동시 최초 관리자 생성은 M0와 동일하게 단일 서버 설치 전제를 따른다.

## 결과
정상 생성·암호화·CHIEF·변경 의무·재시작 중복 방지·정책 위반 생성 생략을 검증했다. 길이 누락은 PasswordPolicyTest에서 실패를 확인한 뒤 보완했다.
