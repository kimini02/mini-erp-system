# M1-6 — 연차·특근 데이터 범위 (KI-02)

## 증상
팀장이 다른 부서의 연차·특근을 전체 목록에서 읽거나 승인·반려할 수 있었다.

## 재현 방법
M1RegressionTest: 범위 밖 목록·승인·반려, 하위 부서의 정상 승인, 관리소장 전체 조회, 일반 사원의 전체 조회 403을 MariaDB에서 확인한다. 최초 M0 기준 실행에서 다른 부서 연차 목록/승인 테스트 2개가 실패했다.

## 원인
전체 조회는 부서 조건이 없었고 AccessPolicy는 역할 계층만 검사했다.

## 검토했지만 버린 방법과 이유
화면 또는 조회 후 자바 필터링은 정보 노출을 막지 못한다. M2에서 바꿀 연차·특근 업무 로직의 재작성은 제외한다.

## 선택한 방법
LEAVE_ADMIN 권한과 ScopeFilter로 SQL에서 요청 ID를 제한한다. 승인·반려는 기존 계층 판정 전에 동일 범위를 확인한다. 기존 상하 역할 결재 규칙과 취소 규칙은 유지한다.

## 부작용·남은 위험
기존 특근 단건 GET은 팀장의 타 부서 조회를 허용하는 별도 경로가 남는다. 이번 지시는 /all과 승인·반려에 범위 적용을 한정하므로 추가 수정하지 않았다(결정 필요). 연차 승인 동시성은 KI-03/M2에 남긴다.

## 결과
부서 밖 조회 결과 제외와 승인·반려 ACCESS_DENIED, 하위 부서 정상 처리, 관리소장 전체 목록, 일반 사원 403을 검증한다.
