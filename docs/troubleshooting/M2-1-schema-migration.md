# M2-1 — 결재 문서·연차 원장 이관

## 증상
v1의 휴가·특근은 각자 결재자와 상태를 갖고, 연차는 사용자 숫자 세 칸에 저장된다. 공통 결재선과 예약·사용 이력을 저장할 수 없다.

## 재현 방법
M2DataMigrationTest가 Testcontainers MariaDB 10.11에 V1·V2를 적용하고 사원 3명과 PENDING/APPROVED/REJECTED/CANCELLED 휴가·특근 8건을 만든다. 기존 잔여 조회와 같은 계산(remaining_annual_leave − 진행 중 신청 일수)을 저장한 뒤 V3를 실행한다.

## 원인
업무 본문과 결재 상태가 합쳐져 있고 연차 예약이 원장 없이 신청 목록에서 계산된다.

## 검토했지만 버린 방법과 이유
신·구 구조를 동시에 기록하는 방법은 명세 0장의 단일 이관 결정과 다르다. V1·V2를 수정하는 방법도 기존 설치 이력을 바꾸므로 쓰지 않는다.

## 선택한 방법
V3에 결재 양식·단계·문서·결재선·이력·번호 발급·품의·알림·연차 원장을 생성한다. 기존 신청을 문서와 본문으로 이관하고, 연차 숫자는 GRANT/USE 및 진행 중 RESERVE로 옮긴다. 원본 반려 사유는 결재 이력에 보존한다. 문서번호는 양식·연도 안에서 생성 시각과 원래 id 순서로 부여한다.

ERD 외 보조 컬럼: manual_line은 재기안 시 수동 결재선 복사 여부, rule_label은 이미 상신한 규칙 설명의 스냅샷, created_at/updated_at은 임시 저장 순서와 기존 시각 보존을 위해 둔다. 모두 명세 응답·동작에 필요한 메타데이터다.

## 부작용·남은 위험
- v1 연차 숫자에는 귀속 연도가 없다. 한국 시각의 이관 연도에 GRANT/USE/진행 중 RESERVE를 묶어 보존한다. 과거 연도별 내역은 복원할 수 없다(결정 필요).
- v1 PENDING 행의 approver_id는 NULL일 수 있다. 명세의 “있으면”대로 해당 문서는 결재선 없이 보존한다. 관리자가 임의 결재자를 자동 배정하지 않는다. 원문서 회수 후 재기안으로 새 규칙을 적용할 수 있다(운영 확인 필요).
- 숫자 세 칸이 이미 불일치한 DB에서는 명세의 total/used 이관과 raw remaining 보존을 동시에 만족할 수 없다. 운영 적용 전 백업·불일치 점검이 필요하다. 이번 테스트는 일관된 기존 데이터를 대상으로 한다.
- 이 커밋은 스키마 이관 단위다. 새 스키마의 운영 매핑·처리기는 다음 작업에서 맞추며, 이 커밋만 배포해서는 안 된다.

## 결과
Java 17 + Docker에서 `./mvnw -Dtest=M2DataMigrationTest,M1DataMigrationTest test`: 2개 성공, 실패·오류·건너뜀 0. 사원 3명의 이관 전후 실사용 가능 잔여가 모두 같다. 상태 4종, 번호·발급 순번, 결재선 스냅샷, 반려 사유, 반차 이름과 이전 컬럼 삭제를 검증했다. M1 이관 회귀는 대상 버전을 2로 고정하여 해당 단계의 계약을 계속 검사한다. 로컬 개발 DB는 접속하지 않았다.
