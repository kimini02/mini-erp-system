# M2-3 — 결재선 규칙과 스냅샷

## 증상
단일 결재자만 저장하던 구조로는 부서장·상위 부서장·역할·지정 사원 규칙과 상신 당시 조직 정보를 보존할 수 없다.

## 재현 방법
M2DocumentIntegrationTest에서 일반 부서장, 본인 건너뜀, 상위 부서장 대체, 중복 건너뜀, 공석, 상신 후 부서장 교체를 검사한다. 미리보기에서는 첫 단계 성공 뒤 두 번째 단계 공석도 별도로 확인한다.

## 원인
규칙과 실제 결재자를 분리하지 않으면 조직 변경 시 진행 중 문서의 결재자가 달라진다.

## 검토했지만 버린 방법과 이유
매번 현재 부서장을 조회해 승인 권한을 정하는 방식은 진행 중 문서의 담당자가 바뀌므로 버렸다. 결재자를 못 찾으면 자동 승인하는 방식도 명세가 명시적으로 금지한다.

## 선택한 방법
상신 시 규칙을 ACTIVE 사원으로 해석하고 이름·직급·부서를 approval_lines에 고정한다. 참조는 상태를 갖지 않는다. 공석으로 해석에 실패하면 422 APPROVER_NOT_FOUND, 모두 정상 해석한 뒤 본인/중복 처리로 남은 결재자가 없을 때만 자동 승인한다. 미리보기는 성공한 단계와 실제 ERROR 단계를 함께 표시한다. 수동 목록은 allow_line_edit를 확인하고 같은 본인·중복 규칙을 적용한다.

## 부작용·남은 위험
명세의 역할 담당자 “아이디 오름차순”은 사용자 기본키 id 오름차순으로 구현했다. 로그인 아이디 순서가 의도였다면 정책 확정이 필요하다. 역할 보유자가 여러 명인 경우의 장기 배정 정책도 명세가 남긴 결정 필요 항목이다.

## 결과
M2DocumentIntegrationTest에서 정상·본인·공석 대체·중복, 공석 오류, 상신 후 담당자 스냅샷 유지와 자동 승인 원장 반영을 확인한다. 최종 실행 결과는 M2-4 문서에 기록한다.
