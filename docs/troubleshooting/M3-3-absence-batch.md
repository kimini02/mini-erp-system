# M3-3 — 결근·퇴근 누락·사후 휴가 재판정

## 증상
출근하지 않은 날과 퇴근 누락을 다음 날 확정할 경로가 없고, 출근 뒤 반차 승인도 기존 판정에 반영되지 않았다.

## 재현 방법
M3BatchTest에서 출근·14시 퇴근 뒤 오후 반차를 승인하고 다음 날 00:10 Clock으로 배치를 실행한다. 종일 휴가·결근·퇴근 누락·입사 전·퇴사자·주말·공휴일·입사일 NULL 사례도 검증한다.

## 원인
당일 출근만으로 하루 결근/누락을 확정할 수 없고, 휴가 승인이 나중에 발생할 수 있다.

## 검토했지만 버린 방법과 이유
기존 판정을 무조건 INSERT하거나 새 라이브러리로 배치 자체를 잠그는 방식은 필요하지 않다. 실패 기록을 업무 트랜잭션 안에 넣으면 함께 롤백되어 실패 흔적이 사라진다.

## 선택한 방법
한국 시각 00:10 스케줄러가 Clock의 전날을 동일 서비스에 전달한다. ACTIVE/입사일(없으면 계정 생성일) 기준으로 새 행을 만들며, 기존 행은 저장된 근무시간 스냅샷으로 승인 휴가를 다시 확인해 판정한다. 사용자 행을 ID 순서로 잠그고 사용자·날짜 유니크를 유지한다. 동일 결과면 업무 값뿐 아니라 judged_at/updated_at도 바꾸지 않는다. 실행 이력은 별도 트랜잭션으로 SUCCESS/FAILED를 남긴다. 테스트에서는 스케줄 실행을 끄고 같은 서비스를 직접 호출한다.

## 부작용·남은 위험
현재 users에는 퇴사일 이력이 없다. 현재 RETIRED인 사람의 새 결근은 만들지 않지만 과거 재직 기간을 정확히 복원할 수 없다. retired_date 추가 여부를 사용자에게 질문했으며 승인 없이 새 사원 컬럼/API 변경은 하지 않았다. 배치 실행 이력은 실행마다 쌓이고 근태 결과가 멱등이라는 의미다. DB 자체가 불능이면 실패 이력 기록도 불가능하다.

## 결과
M3BatchTest는 2회 실행 결과의 전체 근태 행 동일, 오후 반차로 EARLY→ON_TIME, 휴가 LEAVE·결근·MISSING, 비근무일/입사 경계 제외, 강제 저장 실패의 근태 전체 롤백+FAILED 이력 보존을 검증한다. 테스트 초기에는 실행 간 fixture가 섞여 실패하여 근태/배치 이력을 매번 초기화했다. 운영 문제의 수정 전 수치로 세지 않는다.
