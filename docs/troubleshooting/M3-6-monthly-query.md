# M3-6 — 월간 근태표·상세·CSV·재판정

## 증상
사원×날짜 근태표와 근거 상세, 권한 범위를 갖춘 CSV·재판정 경로가 없었다.

## 재현 방법
M3MonthlyTest에서 50명×31일=1,550개 근태를 만들고 실제 API 응답을 검사한다. MariaDB에서 같은 SQL의 근태 유니크 인덱스를 IGNORE INDEX한 비교군과 원본을 각각 예열 3회·측정 9회 실행한다.

## 원인
날짜 또는 사원마다 개별 조회하면 요청 수가 늘고 빈 날짜·퇴사 경계를 일관되게 만들기 어렵다.

## 검토했지만 버린 방법과 이유
화면/자바에서 권한 범위를 거르는 방식은 제외했다. 강제 FORCE INDEX 없이 실제 계획을 확인한다. 전체 애플리케이션 인증/권한 조회까지 한 SQL이라고 주장하지 않는다.

## 선택한 방법
재귀 날짜 CTE와 SQL에서 범위를 제한한 사원, 근태·휴일·승인 휴가를 한 데이터 쿼리로 읽는다. 빈 사원 목록도 날짜를 반환한다. 사전 권한·부서 확인은 별도이며, 선택 부서 검증 1회+표 데이터 1회 이후 셀별 추가 조회는 없다. 퇴사일·입사일과 기존 퇴사자의 기록 유무는 d689d15 확정 규칙을 따른다. CSV는 UTF-8 BOM과 따옴표 이스케이프, 수식 시작 문자 보호를 적용한다. 재판정은 ALL 범위와 U 권한을 확인한 뒤 결근 배치의 같은 코드를 호출한다.

## 부작용·남은 위험
결정 필요: 상태 변경 이력이 없어 과거 휴직·재입사 기간을 복원하지 않는다. 근태 행이 없는 상세의 근무시간은 현재 설정이다. 조회 시간은 로컬 Docker 측정값이며 운영 SLA가 아니다.

## 결과
M3MonthlyTest 3개 통과(최종 전체 결과는 M3-10 참조). 첫 성능 실행: 데이터 쿼리 1회, 근태 a 조인 type=eq_ref, key=uk_attendances_user_date, 예상 rows=1. 중앙값 인덱스 제외 349.327ms → 적용 19.291ms. 범위 밖 부서/사원 403, 재판정 거절 시 실행 이력 없음, CSV BOM, 퇴사일 이후 NONE, 기존 퇴사자 기록 있는 달만 포함을 검증했다.

### 추가 회귀 — 다음 날 퇴근의 판정 근거
지각 후 다음 날 00:10에 퇴근하면 out_result는 ON_TIME인데, 설명을 LocalTime으로만 비교하여 ‘조퇴도 기록됨’이 붙었다. M3MonthlyTest.scopeDetailCsvAndRejudgeEnforceSamePermissions의 추가 단언은 수정 전 1/1 실패했다. 저장된 out_result가 EARLY일 때만 조퇴 설명을 붙이도록 고쳐 1/1 통과했다. 같은 검증에서 팀장에게 U 동작을 임시로 부여해도 DEPT_TREE라 재판정이 403임을 확인했다.
