# M3-7 — 근태 정정 결재 처리기

## 증상
구 직접 수정 경로를 닫은 뒤에는 근태를 승인 근거와 함께 정정할 수단이 필요했다.

## 재현 방법
M3AttendanceFixTest에서 지각 기록을 정정 문서로 상신·승인하고, 반려/회수·날짜 범위·중복·알림 저장 실패·재승인을 검사한다.

## 원인
근태를 직접 수정하면 승인 이력과 업무 변경의 트랜잭션이 분리된다.

## 검토했지만 버린 방법과 이유
approval 서비스에 근태 타입 분기를 추가하지 않는다. 승인 이후 비동기 정정은 문서와 근태의 불일치를 만들므로 제외한다.

## 선택한 방법
attendance.handler의 ApprovalFormHandler 구현만 추가한다. 문서의 사용자 행 잠금 안에서 진행 중 동일 날짜를 검사하고 상신 순간 before를 서버가 저장한다. 승인과 근태 갱신·fix_document_id·알림은 기존 결재 트랜잭션 안에서 처리한다. 승인된 퇴근만 정정도 명세가 허용하므로 absent=false를 이후 재판정에서도 보존한다. 부분 정정값과 기존 반대편 시각을 합쳐 시간 순서가 잘못되면 400으로 롤백한다.

## 부작용·남은 위험
결정 필요: 과거 근무시간 이력이 없으므로 기록이 없는 날의 신규 정정 행에는 현재 부서/회사 근무시간을 복사한다. 기존 행은 저장된 과거 스냅샷을 유지한다. 반복 정정의 전 값은 각 결재 문서에 남는다.

## 결과
M3AttendanceFixTest 4개 통과. 알림 저장을 강제로 실패시키면 결재 IN_PROGRESS·기존 근태·기존 알림 수가 유지되고, 이미 승인된 문서의 재승인 409도 새 알림을 남기지 않는다. 초기 실패 주입이 트랜잭션 프록시를 건드려 실패한 테스트 설정은 실제 spy 대상으로 고쳤다. 운영 버그 전후 수치로 세지 않는다.
